## 方法与环境

GPU：设备 0，NVIDIA RTX A6000；CUDA Runtime 13.1；Release 构建，double、32 位索引。
使用既有 Jacobi + AMG + 右预条件 BiCGStab，并增加恒等预条件子作为无预条件对照。
未使用 cuSOLVER，未为使算例通过而更换矩阵或放宽容差。

没有读取原工况右端项，而是选择确定性的非恒定制造解：

```text
xExact[i] = 1 + 0.25*sin(0.013*i) + 0.125*cos(0.007*i)
b = A*xExact
xInitial = 0
rtol = 1e-8, atol = 0, maxIterations = 1000, residualRefreshInterval = 50
```

右端项由主机端逐行、long double 累加后舍入为 double。
求解后重新在主机计算 A*x，独立校验相对残差和相对解误差。
PASS 要求求解报告收敛、主机相对残差不超过 1.01e-8、相对解误差不超过 1e-4。
制造解测试验证线性求解路径，不代表原 CFD 工况或物理解的正确性。

## 旧实现失败的原因

旧实现三者都在 setup 阶段失败，尚未执行 AMG 预条件的外层迭代。
错误为 `cusparseSpGEMM_workEstimation: insufficient resources`。
失败时的稀疏乘法规模如下，m、k、n 对应 `(m*k)*(k*n)`：

| 数据集 | m | k | n | 左矩阵非零数 | 右矩阵非零数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Kvlcc | 156586 | 307024 | 156586 | 64902309 | 12730546 |
| Suboff | 189761 | 339932 | 189761 | 82803578 | 14582120 |
| JBC | 232225 | 407222 | 232225 | 99961659 | 17690848 |

这些尺寸定位到 Galerkin 中 `(R*A)*P` 的第二次乘法，左矩阵是中间结果 R*A。
原矩阵仅有约 243 万至 430 万条目，但中间结果已显著增密。
根因是 setup 偏离参考：顺序贪心配对与平滑延拓导致 Galerkin 中间算子膨胀。
本次恢复参考的完整聚合和直接坐标归并，去除了这些乘法；没有靠扩大 SpGEMM
工作区、延拓截断或数值丢弃来绕过问题。

## 复现

构建后从项目根目录运行：

```bash
./build/example/solve-matrix data/kvlcc-351k-Velx-1000.mtx amg
./build/example/solve-matrix data/kvlcc-351k-Velx-1000.mtx amg w
./build/example/solve-matrix data/kvlcc-351k-Velx-1000.mtx amg f
./build/example/solve-matrix data/kvlcc-351k-Velx-1000.mtx identity
```

其余两个文件同样调用。程序退出码：0 为双重校验通过，2 为数值未达标，1 为输入或执行异常。
原始日志保存于 `build/real-cases/*-native-{v,w,f}.log`，该目录不纳入 Git。
真实矩阵测试不加入常规 CTest，避免依赖私有数据及占用大量资源。
常规测试包含独立解析测试和小矩阵端到端读取、求解、CPU 校验测试。

单元测试独立对照主机基准的强图、匹配、吸收、成员表与 Galerkin 结果，并用独立主机
递归对比 V/W/F 的数值动作，覆盖 float/宽索引、线性、别名、零平滑及粗层 fallback。
本次完整 CTest 的 97 项均通过，Doxygen 构建无警告；六项新增 AMG 测试和 Kvlcc
真实矩阵 F-Cycle 的 Compute Sanitizer memcheck 均为零错误、零泄漏，粗层与双精度
循环的 synccheck 为零错误。安装后的独立 CMake 使用方也通过了读取、求解和主机校验。
